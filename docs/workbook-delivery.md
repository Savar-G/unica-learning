# Confirm delivery of a numbered workbook

Open a shipped workbook under Admin > Workbooks. Enter the date and time when it arrived at the family's home. The form shows the family's time zone in plain words, such as "Toronto time". Press **Confirm workbook delivered**. Reload shows the saved time and who recorded it. The workbook status remains `shipped`.

Each numbered workbook needs its own receipt. Repeat the same confirmation safely. An ordinary repeat confirmation with a different time is refused. To fix a wrong time, choose **Correct delivery time** and enter the correct time and a short reason. Each correction adds an audit entry with the original time, previous time, new time, reason, admin, and server time. The original receipt and earlier corrections stay unchanged. The receipt's actual delivery time and server record time are separate. No old receipt is inferred from a shipment, an email, a card Boolean, or a Stripe date.

For workbook 1, save its receipt before using **Workbook delivered: start plan** under Plans and delivery (`/admin/next-steps`). The separate billing confirmation and existing Stripe start behavior remain. Recording any delivery makes no billing request. Workbook 2 and later deliveries do not restart a plan.

`confirmDelivery`, `correctDelivery`, `DeliveryStore.receipt`, and `deliveryDeadlines` are the public interfaces in `src/lib/workbook-delivery.ts`. The Supabase store uses the current session. The database checks live admin membership, workbook identity and shipment, time validity, uniqueness, and family freeze in one transaction. Repeated confirmations return the original actor, audit ID, and server time. An explicit correction uses the last audit ID as its version. Repeating its request ID is safe. Two corrections from the same version cannot overwrite each other. The reader projects the latest correction as `deliveredAt` and keeps `originalDeliveredAt` and the correction audit separately. Both deadline anchors use that effective time, including corrections after the reminder clock has started. A correction does not resend or recall an email.

The local input uses minute precision. It rejects invalid dates, clock gaps, delivery before shipment, and future delivery. Repeated clock times select the earlier instant. Deadline calculations preserve the local clock through `family-time.ts`, including its dated zone rules and its first-valid-instant rule for clock gaps. The stored time zone includes the explicit override choice for postal exceptions.

It must read this workbook's receipt and call `deliveryDeadlines`; no receipt means no delivery-based anchor. This slice neither creates scan triggers nor sends scan reminders.
